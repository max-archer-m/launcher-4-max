# 需求简报：产品基础与当前范围

> 英文公共语义源：[product-foundation.md](product-foundation.md)。两种版本需要保持实质一致。

## 职责

本文档定义产品问题、证据边界、目标用户、当前能力范围、跨功能需求、数据边界和产品级验收约束。它不重复页面交互流程或精确表现数值；这些事实由[契约路由](#契约路由)中链接的产品契约负责。

## 问题

作者以 Android 手机为主要设备，通常使用 Samsung 和 Google 手机。作者每次进入主屏幕或查找应用时都会使用 Launcher。目前没有可靠的使用时长或频率测量。

现有产品无法同时满足作者对 Home 与 Drawer 结构、明确布局约束、低视觉噪声和个人实用定制的偏好。因此，作者希望先建立一款适合自己长期日常使用的 Android Launcher。

## 证据边界

### 已知事实与作者经验

- 作者长期使用 Android，并使用过系统与第三方 Launcher。
- 当前问题证据来自作者持续使用经验及对自身需求的理解。
- 目前没有使用次数、任务耗时、访谈、外部用户反馈或市场调研数据。

### 待验证假设

- 相比无限制定制，有限且有意的布局规则可能更容易持续形成美观、舒适且简洁的日常 Home。
- 其他 Android 用户是否存在相同需求尚未验证。
- 产品未来是否应通过 GitHub 或应用商店发布尚未验证。

## 项目动机

- 产品动机：建立一款适合作者长期日常使用、由作者拥有的主屏幕工具。
- 学习动机：通过真实项目学习 agent 系统并积累 agent 工程经验。

学习目标可以影响流程和复盘，但不能替代用户价值、产品验收或质量标准。

## 目标用户与场景

主要用户是作者。产品取舍首先依据作者能否可靠地日常使用。人体工学主要针对右手持机并由右手拇指输入，以及左手持机并由右手点击；其他姿势属于次要目标。

目前没有明确的次要用户。未来可能发布不代表已经证明更广泛需求，也不会自动扩大当前用户范围。

主要场景包括：

- 进入 Android 默认 Home。
- 从 Home 进入 Drawer，查找并启动应用。
- 打开 Settings，配置维持基本 Launcher 实用性所需的能力。
- 在没有网络连接时完成以上核心任务。

## 产品目标

为作者提供适合长期日常使用、完全本地并遵循最小权限原则的 Android Launcher，通过 Home、Drawer 和 Settings 完成基本主屏幕实用闭环。

当前范围关注实用性，不涵盖大众市场适配、广泛定制或网络信息。作者希望获得其他产品缺失或收费的能力，这属于期望，不是市场证据或当前验收条件。

## 平台与交付边界

- 最低支持版本：Android 12（API 31）。
- 当前物理验证设备：Android 16 的 Samsung Galaxy S23 Ultra 与 Android 17 的 Google Pixel 8。
- 最低版本验证环境：Android 12/API 31 模拟器，除非未来具备代表性物理设备。
- 设备范围：仅普通 Android 手机竖屏。Launcher4Max 只以竖屏呈现；旋转请求不产生横屏布局，任何界面都不定义横屏几何。
- 排除设备：横屏、折叠屏、平板、桌面模式和外接显示器适配。横屏呈现保持排除，直到明确完成适配。
- 分发边界：仅通过 GitHub 仓库公开发布。不进行应用商店提交、网站 APK 或其他分发渠道。创建 GitHub Release、tag 或上传 APK 仍须单独授权。
- 商店 target API、审核和数据披露要求不是当前交付门槛，因为不包含应用商店分发。

产品兼容边界要求 `minSdk` 31。当前配置的 `compileSdk`、`targetSdk` 和版本数值由[开发指南](../development.zh-CN.md)维护；公开分发的 target API 门禁由[发布治理](../release.zh-CN.md)维护。当前产品需求不保留历史版本的 SDK 选择指令。复核日期：2026-08-28。

## 当前产品范围

### 范围内

- Home：一个不分页、不可折叠的默认主屏幕，固定时间和日期位于一个可纵向滚动、全宽的收藏主列表上方，并提供 Drawer 手势入口；在 Launcher4Max 不是设备默认 Launcher 时，该固定信息区与收藏主列表之间还展示一个可关闭的默认启动器提示。
- Favorites：一个由全宽纵向模块与单行横向收藏织带组成的有序异构序列，不设置人为模块数量上限。一个可启动身份只归入一个模块；纵向模块保存模块级图标尺寸、名称（文字）尺寸、名称位置和每行数量，织带使用固定样式。
- 收藏编辑：由 Home 与 Drawer 契约定义的明确新增、移除、移动、排序、调整尺寸、确认、取消、最近一次移除撤销以及 Drawer 拖动收藏行为。
- 锁屏：适用于 Home 合格空白区域的可选、用途受限无障碍服务能力，由用户绑定到它的快捷操作槽位触发；它不阻断独立 Launcher 路径。
- 快捷操作：两个用户可配置的 Home 基础信息区空白槽位，各自绑定 `无操作`、`编辑模式` 或 `锁屏`，默认均为 `无操作`。
- Drawer：Android 暴露来源中成功读取的全部可启动条目，包括可用时的应用分身和工作资料条目，并在普通模式提供本地应用名称搜索及用户选择的背景不透明度：`0`（壁纸清晰）至 `100`（纯色表面）；全新配置默认 `50`。非当前资料的局部读取失败不阻断其他资料提供的可用条目。
- 应用操作：Home 与 Drawer 均提供应用信息和平台快捷操作；Home 另提供取消收藏、编辑，以及仅在平台可安全定位所选身份时提供的卸载；Drawer 在相同平台约束下提供卸载。
- Settings：适用的默认 Launcher 状态与系统入口、快捷操作设置（含锁屏授权入口与披露）、Privacy、License、仓库链接和版本信息，并通过系统文档选择器提供收藏、快捷操作绑定与 Drawer 显示设置的本地手动备份和恢复。
- 根据系统区域自动选择英文或简体中文资源，其他区域回退英文。
- 核心任务离线可用、核心数据本地存储，并且只使用可追溯到必要核心能力的权限。

### 范围外

- 主要目的为美学优化的视觉精修。
- 小组件、类似文件夹的分组、Home 分页、主题和无限制布局或视觉定制。
- 一键清除或云端删除全部本地配置。
- 天气等联网信息。
- 账户、云同步、自建服务器或跨设备备份。
- 行为分析、自动排序、推荐、AI 辅助或 agent 集成。
- Android Private Space 访问、呈现、管理、收藏或恢复，包括声明 `ACCESS_HIDDEN_PROFILES`。
- 商业模式验证、正式商店发布或大众市场适配。

范围外能力不属于当前契约，但不代表永久否决。广告、推荐信息流和最大化参与度的设计继续受到项目 overview 的长期边界约束。

## 可叠加需求

横屏支持、折叠屏和平板适配、主题、天气信息和小组件可以作为未来可叠加能力评估。类似文件夹的分组与当前直接访问原则冲突，因此排除。

一项能力能够独立实现，并不意味着它自动进入当前范围，也不能绕过产品、隐私、安全、验证或维护审查。

## 功能需求

- Launcher4Max 可以作为 Android Home 入口，并提供 Home–Drawer–Settings 实用闭环。
- 当 Launcher4Max 不是设备默认 Launcher 时，Home 展示一个可关闭提示；点击它打开与 Settings 默认主屏幕条目相同的系统目标，并且不改变任何 Launcher4Max 状态。
- Home 展示系统时间与日期、本地保存的收藏，并启动选中的身份。
- 收藏身份区分主应用、应用分身和工作资料条目，不能只按包名去重。
- 收藏变更由用户明确触发、在本地持久化，并保持有效目标与顺序，不产生重复或静默改投。
- Drawer 在 Launcher4Max 的 Android 角色与最小权限边界内展示、本地搜索并启动可靠的可用清单。
- 清单刷新、来源局部失败、永久消失、Loading 和 Error 行为应保留可用路径，不能把不确定数据转化为破坏性结论。
- 应用操作和 Settings 只打开对所选身份有效的目标；已经定义的本地失败反馈不得破坏收藏状态。
- Launcher4Max 可以将完整收藏模块、Drawer 显示设置与快捷操作绑定状态备份到一个用户选择的本地文件，并通过确认后的原子替换恢复，不依赖网络、不做自动备份。
- 只有用户把快捷操作槽位绑定为锁屏、启用适用无障碍服务并在合格区域执行绑定手势后，锁屏才请求系统锁屏操作。
- 英文与简体中文是完整支持的资源集；其他区域回退英文，不提供应用内手动语言选择。
- 核心 Home、Drawer、应用启动和 Settings 任务离线可用。

契约路由表中的详细交互结果和精确表现数值同样属于验收要求，但不在本文重复。

## 非功能需求

- 核心路径不得因 Launcher4Max 崩溃、无响应或破坏本地配置。
- 必须遵循最小权限；权限被拒绝只能影响依赖该权限的能力。
- 用户可见文案支持本地化，并继续适用系统字体缩放。
- 当前数据保持本地，不引入账户、分析、服务器或云同步。
- 验证结论必须注明实际证据，并遵循[验证指南](../validation.zh-CN.md)。

性能预期是作者的主物理设备跑通已接受的核心旅程。不追求性能、功耗、内存或启动响应的数值门槛，这些也不是产品级完成条件。

## 产品级验收条件

- 作者可以在支持的设备边界内离线完成 Home–Drawer–Settings 闭环。
- Home 默认启动器提示只在 Launcher4Max 不是默认 Launcher 时出现，被其关闭控件抑制后当天不再展示，从不改变 Launcher4Max 配置，并打开与 Settings 条目相同的系统目标。
- 点击可见的可启动身份会启动预期应用。
- Drawer 不遗漏、重复或错误识别成功读取的 Android 来源返回条目；局部失败来源的条目可以缺失，但不阻断已有 Content。
- 普通 Drawer 搜索按照应用显示名称过滤可靠的本地应用清单，不访问网络、不改变已选排列，也不引入第二套应用顺序。
- 需要隐藏资料访问的 Private Space 身份不进入清单或权限声明。
- 收藏身份、模块目标、应用顺序、适用的纵向模块样式和模块顺序在适用重建后不会意外丢失、重复或改投。
- 失败或不确定读取与有效空数据保持可区分，并且不会覆盖最后一次可靠收藏状态。
- 权限拒绝或撤销只影响依赖能力，独立 Launcher 路径保持可用。
- 本地备份与恢复在不依赖网络、不做自动备份且不损失无关配置的情况下，保存并恢复完整的收藏、显示设置与快捷操作绑定状态。
- 英文、简体中文和英文回退按照系统区域解析。
- 本次交付明确选定范围和证据基线内适用的页面行为与表现契约得到满足。
- 用于日常使用验收的结果应在作者适用的物理设备上观察；仅完成实现并不足够。

## 成功评估与约束

核心成功是 Home、Drawer 与 Settings 为作者持续日常使用形成可靠的最小实用闭环。成功以作者观察到的体验判断；未收集的外部用户意见不是证据。“美观、舒适、简洁”尚未转换为可观察标准，不是当前验收条件。

## 用户控制

产品允许用户维护 Home 收藏并使用独立 Settings 入口，并通过系统文档选择器提供收藏、快捷操作绑定与 Drawer 显示设置的本地手动备份和恢复；它不提供一键清除、云端删除、自动备份或云端恢复全部配置。用户可以通过 Android 系统设置清除应用数据。收藏变更来自用户明确操作，语言跟随系统区域而不是观察到的行为。

## 本地数据边界

- 持久用户内容数据包括有序收藏模块、模块类型、稳定收藏身份与位置，以及适用的纵向模块图标尺寸、名称（文字）尺寸、名称位置和每行数量。一个稳定身份只有一个模块目标，不能跨模块重复。
- 持久本地配置还包括已经选择的 Drawer 应用图标尺寸、应用名称尺寸、名称位置、每行项目数量、分组锚点表现、背景不透明度百分比，以及每个 Home 基础信息区槽位的快捷操作绑定。每次有效变更均作为一份完整配置状态保存。
- 主应用、应用分身和工作资料身份必须保持可区分，不能只按包名存储或去重。
- 最近一次符合条件的应用移除快照是临时撤销状态，不是持久撤销历史。
- 用户最后一次关闭 Home 默认启动器提示的本地日期是持久呈现状态。它由用户控制，不属于应用使用历史，也不包含在备份文件中。
- 时间与日期来自设备系统，不保留历史记录。
- Launcher4Max 不收集或存储无障碍窗口内容或事件、通知、联系人、位置、剪贴板内容、文件、照片、稳定设备标识、应用使用历史或分析事件。
- Launcher4Max 没有账户、云同步、服务器、云备份或跨设备备份。Android 云备份和设备迁移备份继续对 Launcher4Max 收藏与显示设置数据禁用；仅提供下文描述的用户主动本地备份。
- 用户主动本地备份通过系统文档选择器，把包含完整收藏模块、Drawer 显示设置与快捷操作绑定状态的单个带 schema 版本号的 JSON 文件写入用户选择的位置。该文件由用户管理，位于 Launcher4Max 应用私有存储之外，永不上传或自动写入。

## 依赖与风险

- Android Home 角色、应用枚举方式、应用分身可见性和相关声明或权限需要持续技术与隐私审查。
- 未来支持 Private Space 需要单独的作者批准能力，并重新进行交互、权限、隐私、兼容性和验证审查。
- 当前证据只代表作者，无法支持大众市场需求结论。
- 学习 agent 系统可能促使流程或技术复杂度超过产品需要；应通过明确范围变更加以控制。
