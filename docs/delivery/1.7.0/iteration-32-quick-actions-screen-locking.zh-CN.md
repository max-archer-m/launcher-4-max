# 迭代 32：快捷操作与屏幕锁定

> 适用版本契约：[1.7.0 交付](delivery.zh-CN.md)。本契约只定义经授权的交付边界；它不拥有执行状态、证据、提交或结果，本身不授权生产实现、提交、推送、打 tag 或任何发布动作。

## 目标

严格按已验收契约交付快捷操作契约：两个可配置的 Home 基本信息快捷操作槽位及其绑定、持久化与备份纳入；快捷操作设置子页及其槽位行、常显的锁屏服务状态行与锚定单选弹窗；以泛化的屏幕锁定表述取代双击锁屏；移除独立的"双击锁屏" Settings 项；并将用途受限无障碍服务移入 mainline，使被绑定的 Screen lock 手势在所有构建类型中存在。

## 可观察结果

在主设备上，全新配置将两个快捷操作槽位呈现为 No action，且任何基本信息手势不触发任何动作。选择槽位打开锚定单选弹窗，提供 No action、Edit mode、Screen lock 三个选项，且无跨槽校验。绑定 Edit mode 后，被绑定手势进入 Home 编辑模式；在无障碍服务关闭时绑定 Screen lock 进入已披露的授权流程且不改变已保存绑定；服务启用后，被绑定手势锁屏，锁屏请求失败时呈现契约规定的失败 toast。快捷操作设置子页常显锁屏服务状态行；Back 可返回；进程恢复不恢复该页。Settings 列表不再包含独立的"双击锁屏"项。本迭代之后写出的备份文件包含绑定并可在全新安装中恢复；本迭代之前的备份在方向性兼容规则下仍可无绑定导入。

## 纳入工作

- 双槽快捷操作绑定模型：三个选项、No action 默认值、无跨槽校验。
- 契约规定的合格基本信息空白区上的槽位手势识别：识别阈值与取消路径遵循契约定义的平台行为，绑定为 No action 的槽位不执行任何动作。
- 绑定在本地设置状态中的持久化，及其在手动备份文件内容与本地数据枚举中的纳入。
- Settings 中的快捷操作设置主项与快捷操作设置子页：槽位行、常显的锁屏服务状态行、锚定单选弹窗、Back 语义，以及进程恢复不恢复该页的规则。
- 在服务关闭时绑定 Screen lock 进入的锁屏授权流程，且该流程不改变已保存绑定。
- 泛化的屏幕锁定：无障碍授权入口移至快捷操作设置页，用途受限服务边界与披露流程不变。
- 从 Settings 列表移除独立的"双击锁屏"项及其说明页入口。
- 无障碍服务从仅 debug 源集移入 mainline 源集（含 manifest 声明与配置），应用图在所有构建类型接线真实控制器，保持不变的 fail-closed 请求行为。
- ADR-0004 改写为其现在记录的绑定驱动触发与 mainline 集成。
- 隐私对齐：隐私声明、无障碍披露标题与正文、锁屏说明文案按当前隐私契约更新为"绑定手势"与"屏幕锁定"表述，英文与简体中文同步。
- 所有新增或变更的用户可见文案均提供英文与简体中文字符串，名称完全对齐。
- 聚焦测试源：覆盖槽位解析与默认值、弹窗选择、绑定持久化与备份对齐、授权流程、服务状态行、旧 Settings 项移除。

## 排除工作

- Home 默认启动器提示与应用大小渐缩滑杆，属于迭代 33。
- 任何横屏行为或方向变更。
- 发行边界的产品契约变更与全部发布操作事项，属于迭代 34。
- `1.7.0` 版本标识更新（`versionName`/`versionCode`），除非后续经授权的修订另行指派，仍属版本级收尾事项。
- 用途受限无障碍服务边界的任何变更：不读取内容、不观察事件、fail-closed 的单动作请求均严格保持契约原样。

## 技术变更面

- Home 基本信息手势处理：以槽位解析取代硬编码的双击/长按行为。
- 设置存储：新增绑定字段及版本化持久化，备份序列化扩展。
- Settings UI：新增主项、子页、槽位行、状态行与弹窗；移除旧项及其说明页。
- 导航：新增子页目的地及其 Back 与恢复规则。
- 无障碍集成：服务及其 manifest/配置从 `app/src/debug` 移入 mainline 源集；应用图对所有构建类型的控制器选择。
- 隐私资源：双语披露与声明文案。
- ADR-0004 改写，记录绑定驱动触发与 mainline 集成。
- 测试：上述行为的聚焦本地与仪器测试源。

## 依赖与顺序

本迭代是 1.7.0 序列的第一个迭代，仅依赖记录基线处的已验收契约。其存储、备份与字符串区域与迭代 33 仅在共享资源上重叠；因正式发布物要求 release 构建中存在的锁屏能力，它先于迭代 34 的操作工作。生产实现开始前，实现线必须包含记录的基线。

## 迁移与兼容影响

- 备份 schema 扩展绑定段。无绑定的旧备份按方向性 schema 兼容规则导入，两槽按契约的 No action 默认值解析；更高 schema 版本按契约失败。
- 无绑定字段的既有本地配置按契约默认规则解析为 No action 默认值；原双击锁屏开/关偏好不作映射，因为泛化契约移除了该设置。
- 服务移入 mainline 会改变 release 构建：release 安装在用户进入授权流程后可出现在系统无障碍列表中。该时点之前无升级期行为变化。

## 安全、隐私、权限与许可影响

- mainline 构建中的无障碍服务将其 `BIND_ACCESSIBILITY_SERVICE` 权限带入 release 构建；其用途受限边界（仅锁屏全局动作、不读取内容、fail-closed）不变，披露流程不变。
- 隐私声明与无障碍披露文案必须与实际发布行为完全一致；实现中若发现重大偏差，停止工作并取得作者指示。
- 不引入新的网络、账户或外部服务。

## 风险与未决决策

- 替换硬编码手势不得回归编辑模式进入、锁屏失败 toast 或既有仪器测试覆盖；旧测试应改写而非简单删除。
- 服务 mainline 化会改变 release 构建的 lint 面与系统无障碍列表形态；若引入新条目，须在本迭代内刷新 lint 基线。
- 备份对齐测试必须证明绑定经受备份 → 恢复往返，且旧备份仍可导入。
- ADR 改写是由作者拥有的架构记录变更；本迭代实现已裁决的方向，不重新决策。

## 验收标准

- 全新配置下两槽均为 No action，任何基本信息手势不触发任何动作。
- 每个槽位的弹窗恰提供 No action、Edit mode、Screen lock；选择在重建与重启后持久；跨槽重复选择被接受且无校验。
- 绑定 Edit mode 的槽位通过被绑定手势进入 Home 编辑模式；另一槽位行为不受影响。
- 服务关闭时绑定 Screen lock 进入授权流程且已保存绑定不变；服务启用后，被绑定手势锁屏，失败的锁屏请求按契约呈现 toast 且不重试。
- 快捷操作设置子页常显服务状态行，Back 可返回，进程死亡后不被恢复。
- Settings 列表不含独立的"双击锁屏"项，旧说明页仅可通过契约入口到达。
- 绑定出现在备份文件中并经受备份 → 恢复往返进入全新安装；扩展前的备份无绑定导入。
- 隐私声明与无障碍披露在双语下与发布的绑定手势、屏幕锁定行为一致。
- 所有新增或变更的用户可见文案均提供英文与简体中文字符串，名称完全对齐。
- 普通 Home 交互、Settings 导航、收藏与显示设置的备份/恢复、抽屉行为均无回归。

## 验证要求

除非显式提升，以下为推荐场景：

- 主物理设备旅程：全新状态默认值、双槽弹窗选择、各绑定的手势行为、服务关闭时的授权流程、服务启用与被绑定锁屏手势、失败 toast。
- 设置子页旅程：服务开/关下状态行准确性、Back、进程死亡与恢复。
- 含绑定的备份往返，以及扩展前备份的导入。
- release 构建验证：release APK 中被绑定 Screen lock 手势存在且可用，与迭代 34 的产物工作协同。
- 英文与简体中文资源字符串对齐。
- 普通 Home、Settings、抽屉与备份/恢复旅程回归。
