> 适用版本契约：[1.7.0 交付](delivery.zh-CN.md)。本契约只定义经授权的交付边界；它不拥有执行状态、证据、提交或结果，本身不授权生产实现、提交、推送、打 tag 或任何发布动作。

使项目达到首次公开发布可满足发布治理 `Formal release artifact` 门槛的状态：记录公开 GitHub 发行边界与主设备性能预期的经授权产品契约变更、发布治理留给本项目的操作发布决策、过期仓库 URL 修复、依赖与许可清单，以及面向公众的仓库呈现。

## 可观察结果

产品概览记录仅公开 GitHub 的发行边界，产品基础将性能预期记录为主设备对核心旅程的验收且不设数值门槛。隐私联系资源指向当前仓库。发布治理的剩余决策清单全部定值并记录：共享上下文之下的 APK 目录与保留策略、正式签名密钥保管及其两份独立加密备份、权威构建/签名/摘要/安装/验证命令、tag 命名约定、可观测性处置与分发渠道。仓库呈现面向公众的 README，含安装说明与截图，并存在已记录处置的依赖与许可清单。

## 纳入工作

- 产品契约阶段，在产品契约线上执行并于操作阶段前取得作者验收：产品概览中的发行边界变更（通过 GitHub 仓库的公开发布取代仅作者日常使用边界）与产品基础中的性能预期记录（作者主设备跑通已验收核心旅程；不追求数值性能门槛），各含中文对应文档。
- 隐私联系 URL 资源从原仓库更新为当前 `launcher-4-max` issues 地址，双语同步。
- 发布操作决策，按发布治理指定的位置记录：共享上下文之下的确切 APK 目录及其保留、同步、备份与 Git-ignore 策略；正式签名密钥的格式、参数、安全位置、备份流程与授权签名工作流，含首个正式产物前所需的两份独立加密作者自控备份；权威构建、签名、摘要、安装、升级与验证命令；确切的 tag 命名约定；本发行阶段可观测性与崩溃监控处置；分发渠道及其发布门槛。
- 依赖与许可清单及其处置，含 Settings License 行的第三方 License 呈现决策。
- 公共仓库呈现：面向公众读者的 README 及其中文对应文档、安装说明、已验收界面的截图，以及移除与公共边界矛盾的作者内部性表述。
- 正式产物可追溯性记录：应用于本版本验收 APK 的源提交、签名类别、产物摘要与保留位置约定。
- 聚焦验证：按记录命令构建的 release APK 可安装、可自先前版本升级，并在主设备上跑通已验收核心旅程。

## 依赖与顺序

本迭代跟随迭代 32——其 mainline 无障碍服务是含可用绑定锁屏的发布产物的先决条件。迭代内部，产品契约阶段先于操作阶段；作者验收契约变更后，本契约按修订规则记录新基线，依赖性操作工作继续前实现线必须包含该新基线。正式签名密钥备份要求必须在首个正式产物打包前满足，但创建这些备份是本契约范围之外的作者动作；本迭代只记录流程。

## 迁移与兼容影响

- 无应用状态 schema 变更；发布产物必须支持自先前已安装版本的就地升级旅程。
- 发行边界变更在首个公共产物发布（仍是单独授权动作）之前仅为文档级变更。

## 安全、隐私、权限与许可影响

- 正式签名密钥保管规则适用：任何私有签名材料不得进入 Git 或权威文档；已完成记录仅保存证书 SHA-256 指纹；首个正式产物之前两份独立加密备份必须存在。
- 依赖与许可清单必须覆盖每个随发布依赖，其处置不得与隐私声明矛盾。
- 公共边界提高了隐私声明、无障碍披露与仓库内容的暴露面；其面向公众的准确性属于本迭代验收范围。

## 风险与未决决策

- 操作决策（APK 保留、密钥工作流、命令、tag 命名、可观测性、分发门槛）是经由本迭代记录的作者决策；本迭代负责准备与起草，但不代为决策。
- 可观测性处置可以合法地是"本发行阶段不引入"；记录该决策本身仍是必需的。
- 截图与 README 工作不得披露私有设备内容或作者内部路径。
- 可追溯性约定必须与既有版本标识纪律协调；`versionCode 8` 分配属于版本收尾事项，除非经授权的修订另行指派。

## 验收标准

- 产品概览与产品基础以双语记录已验收的发行边界与性能预期，且本契约在验收后记录修订后的基线。
- 隐私联系资源在双语下指向当前仓库。
- 发布治理的每个剩余决策项均在其指定位置定值并记录，含密钥保管与双备份流程及权威命令集。
- 依赖与许可清单存在且处置已记录，第三方 License 呈现决策已记录。
- 公共 README、安装说明与截图面向公共读者准确呈现产品，中文对应文档对齐。
- 记录的构建、签名、摘要与安装命令可复现验收的 release APK，该 APK 在主设备上安装、升级并跑通已验收核心旅程。
- 任何仓库可见文档中不出现私有签名材料、私有设备内容或作者内部路径。

## 验证要求

除非显式提升，以下为推荐场景：

- 端到端执行记录的权威命令，并对照产出的产物核验摘要与可追溯性记录。
- 在主物理设备上安装并升级 release APK，跑通已验收核心旅程，含迭代 32 的被绑定锁屏手势。
- 以公共读者视角审阅公共 README、截图与隐私相关文档。
- 对照实际依赖树核验依赖与许可清单。
- 核验作者执行密钥备份流程时满足两份独立加密备份要求。
