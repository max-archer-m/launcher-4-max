# 快捷操作交互规格

> 英文语义源：[quick-actions.md](quick-actions.md)。可选锁屏能力及其无障碍边界见 [double-tap-lock.zh-CN.md](double-tap-lock.zh-CN.md)；共享合格空白见 [Home 交互规格](../surfaces/home.zh-CN.md)。

## 目的与范围

快捷操作允许用户把 Home 基础信息区空白手势绑定到产品动作，而不是把这些分配写死在产品规则中。契约只登记两个槽位：

- 基础信息区双击槽位；
- 基础信息区长按槽位。

每个槽位解析为一个动作：`无操作`、`编辑模式` 或 `锁屏`。所有槽位默认为 `无操作`；新安装时空白手势没有任何产品动作。

快捷操作只覆盖这两个已登记槽位。点击时间或日期保持立即打开时钟或日历，应用目标保持普通点击与长按行为，编辑模式内部手势、Drawer 手势以及 Home 其余布局均不可配置，当前契约在收藏主列表或 Home 其他区域没有槽位。未来槽位属于可叠加契约变更。

## 绑定与配置

- 槽位相互独立配置。Launcher4Max 不做任何唯一性、互斥或跨槽位校验：两个槽位可以绑定同一动作，任何绑定都不约束其他绑定。
- 绑定变更立即生效，并针对完整设置状态启动一次独占保存。保存尚未完成时，
  其他绑定变更不可用，但仍可离开页面。保存失败时恢复最近一次成功保存的完整绑定状态，
  显示本地化短 Toast `无法保存快捷操作设置`；已经关闭的页面或弹窗不重新打开。
  后续有效绑定变更可以重试。
- 绑定状态属于手动备份文件的一部分并遵循其 schema 规则；缺失绑定节或字段时恢复为默认值 `无操作`。
- 修改某个绑定不影响另一槽位的识别、进行中的手势识别或其他任何 Home 行为。

## 手势识别

- 两个槽位都作用于 [Home 交互规格](../surfaces/home.zh-CN.md) 定义的基础信息区合格空白。双击必须在该有效空白内开始并结束；长按必须从该空白开始并保持在该平台移动容差内。时间、日期星期及其他所有交互目标均被排除。
- 未来在该区域展示的信息会按其自身内容和交互目标缩减有效区域，但不得占满所有具有实际可操作性的空白。
- 点击时间仍然立即打开时钟；点击日期星期仍然立即打开日历；两者都不为等待可能的第二次点击而延迟。
- 双击槽位采用平台双击时间与移动容差；长按槽位采用平台长按阈值。Launcher4Max 不定义产品专用硬编码阈值。
- 移动超过平台容差、取得过渡所有权的 Home→Drawer 上滑、手势取消或进入排除目标的手势，都会按 [导航](../navigation.zh-CN.md) 取消识别。

## 绑定动作

- `无操作`：被识别的手势不产生产品动作，也不产生反馈。
- `编辑模式`：识别后按其他编辑模式入口的相同规则进入 Home 编辑模式，保持主列表位置
  和采用织带布局的织带位置。流式布局织带没有独立横向位置，并在识别时产生一次平台
  标准触觉。
- `锁屏`：识别后通过 [double-tap-lock.zh-CN.md](double-tap-lock.zh-CN.md) 定义的用途受限无障碍服务请求一次系统锁屏操作。请求成功时不显示 Toast、不震动、无动画或二次确认。服务未启用时手势不产生产品动作，也不打开系统设置；服务已启用但操作不可用或失败时，Home 保持可用并显示短 Toast `无法锁定屏幕`，不自动重试。

## Settings 界面

Settings 包含一个标题为 `快捷操作设置` 的主要设置项，它打开本文件定义的独立页面。页面与弹窗的精确数值属于 [Settings 表现规范](../presentation/settings.zh-CN.md#快捷操作设置页与选择弹窗)。

- 页面标题为 `快捷操作设置`，复用 Settings 页面结构与顶部应用栏，包括其返回控件。本页不单独定义低保真线框图。
- 页面按登记顺序为每个槽位显示一行：`基础信息区双击`，然后是 `基础信息区长按`；每行副标题显示当前动作名：`无操作`、`编辑模式` 或 `锁屏`。
- 页面另外列出下面定义的锁屏服务状态行。页面上的每个条目都带与 Settings 条目相同的右侧箭头，包括两个槽位条目。
- 点击某个槽位行打开一个本地单选弹窗，列出 `无操作`、`编辑模式` 和 `锁屏`。弹窗每个选项条目由一个前置单选指示和其后的动作名组成，并标记当前绑定。弹窗有三条关闭路径：选中某个选项时立即应用预览并启动保存，随后关闭弹窗；点击弹窗外部关闭且不改变任何绑定；系统 Back 关闭且不改变任何绑定。保存失败时恢复原绑定并显示失败 Toast，不重新打开弹窗。
- 选择 `锁屏` 与其他选项一样直接保存该绑定，不弹确认，也不依赖无障碍状态。绑定保存成功后才进入授权流程。若当时服务为 `已关闭`，Launcher4Max 会进入 [double-tap-lock.zh-CN.md](double-tap-lock.zh-CN.md) 定义的锁屏授权流程：本地说明界面与 `打开无障碍设置` 操作，以及该跳转前的显著披露。该流程在弹窗关闭后打开；无论用户取消该流程、同意但未启用服务，还是启用了服务，绑定都保持已保存。若绑定保存失败，则不打开授权流程。
- 选择 `无操作` 或 `编辑模式` 不会打开无障碍流程。
- 从本页返回 Settings 时保留 Settings 此前位置；Settings 自身的 Back 行为不变。

### 锁屏服务状态行

- 该行与当前绑定无关，始终在页面上可见。它是 Launcher4Max 无障碍锁屏能力的常设通道：用户可以随时看到该能力是否已启用，并进入其说明与授权流程。
- 标题为 `锁屏`。所需 Launcher4Max 无障碍服务已经启用并连接时副标题显示 `已开启`，其他情况显示 `已关闭`。
- 它打开 [double-tap-lock.zh-CN.md](double-tap-lock.zh-CN.md) 定义的本地说明界面（展示当前状态、用途、隐私边界和 `打开无障碍设置` 操作）。该跳转前按 [privacy.zh-CN.md](privacy.zh-CN.md#锁屏显著披露) 展示显著披露。
- 从系统设置返回后立即刷新副标题；Android 状态仍是唯一权威来源。

## 验收意图

- Given 默认绑定，when 用户在基础信息区合格空白双击或长按，then 不发生任何产品动作。
- Given 双击槽位绑定为 `编辑模式`，when 在合格空白中识别出双击，then Home 以一次标准触觉进入编辑模式且列表位置不变。
- Given 两个槽位都绑定为 `锁屏`，when 服务已启用且任一绑定手势被识别，then 每次识别都请求一次系统锁屏操作。
- Given 某槽位绑定为 `锁屏` 但服务未启用，when 绑定手势被识别，then 不产生动作与反馈。
- Given 备份包含绑定，when 恢复完成，then Home 呈现与备份完全一致的绑定；Given 绑定节或字段缺失，then 该槽位恢复为 `无操作`。
- Given 默认绑定，when 用户打开 `快捷操作设置`，then 两行副标题都显示 `无操作`，且锁屏服务状态行以 `已关闭` 可见。
- Given 没有槽位绑定 `锁屏` 但服务已启用，when 展示该页面，then 服务状态行仍以 `已开启` 保持可见。
- Given 某槽位绑定为 `锁屏` 但服务未启用，when 展示该页面，then 服务状态行显示 `已关闭`，并打开说明界面。
- Given 服务处于 `已关闭`，when 用户选择 `锁屏`，then 绑定被保存并进入授权流程；取消该流程或服务仍保持未启用都不改变该绑定。
- Given 服务处于 `已关闭`，when 用户选择 `无操作` 或 `编辑模式`，then 不出现授权流程。
- Given 单选弹窗已打开，when 用户点击弹窗外部或触发系统 Back，then 弹窗关闭且任何绑定都不发生变化。
- Given 重新绑定某一槽位，when 用户之后使用另一槽位，then 另一槽位保持其原有绑定。
