# Style Settings Panel Presentation Specification

> Public semantic source: English. Chinese counterpart: [style-settings-panel.zh-CN.md](style-settings-panel.zh-CN.md).

## Responsibility

This document is the single presentation source for the visual surface, setting rows, selectors, steppers, and application-size controls shared by the Drawer and Home style settings panels. [Drawer presentation](drawer.md#display-settings) and [Home presentation](home.md#edit-dock-and-style-settings-panel) own only their host-specific placement, modality, height, content, and surrounding layout. Their behavior specifications continue to own state and action results.

This shared product contract requires one observably identical panel treatment; it does not prescribe a source-code class, framework abstraction, or implementation component boundary.

## Shared panel surface

- The style settings panel uses one resource-backed `darkSurfaceBaseColor` surface with exactly `12dp` corners. Drawer and Home use the same surface color, corner radius, horizontal outer margin, and border without host-specific visual substitutions.
- The panel edge treatment is one `1dp` border in `#6E6E73`, drawn along the panel corner radius. These are the author-accepted current delivery values of 2026-09-09; device comparison may amend them through author acceptance and an update to this specification.
- The panel surface has `0dp` general container padding. Every setting block consists of one non-interactive title line and one content line. A title line is exactly `32dp` high. Standard content lines are exactly `48dp` high; the application-size block is an accepted `56dp` exception. Lines occupy the complete inner panel width, use `12dp` start and end content insets, and vertically center their contents. A read-only informational row (for example the selection prompt or the fixed-style message) is a single `48dp` row.
- Each host owns its setting-block order.
- The shared panel surface does not itself define a Scrim, modal input blocking, outside-click behavior, bottom margin, maximum height, internal scrolling, or attachment to another control. Each host owns those rules.

## Shared selectors and controls

- Related controls that belong to one semantic setting appear together on one content line; for example, the application-arrangement block combines the name-placement selector and the items-per-row stepper on one content line. A content line may scroll horizontally only when its controls overflow the available line width; the title line never scrolls. The contracted acceptance is that content lines do not overflow on the author's designated baseline device (currently the author-designated primary physical device; the Pixel 8 is not currently considered).
- Interaction targets in the panel are at least `40dp x 40dp`. This is an author-accepted exception to the shared `48dp` minimum target, because the panel is not a frequent-touch region and its compact `48dp` content lines otherwise leave no target margin. Visible control size does not define hit geometry.
- A compact two-option selector uses a `140dp x 40dp` dark rounded frame with a light boundary and `2dp` internal padding. It contains two equal `68dp x 36dp` light-filled, borderless rounded thumbs. Centered option labels use medium-weight shared `secondaryTextFontSize` and its line height. Each option retains a target at least `40dp` high and full thumb width.
- Selector thumb and text-color transitions use the same platform or theme short-duration property-animation token, with approximately `200ms` as the reference duration rather than a hard-coded duration.
- Decrement and increment use localized text on approximately `28dp x 28dp` visible rounded backgrounds with `4dp` corners. The items-per-row value uses an approximately `32dp x 28dp` visible background. Each of the three controls retains its own interaction target of at least `40dp x 40dp`; visible background size does not define hit geometry.
- The application-size block combines two three-stop tapering sliders on its accepted `56dp` content line, using the shared `12dp` start and end content insets and one `16dp` gap between them. The two sliders divide the remaining line width equally: the physical-left slider selects the application icon size and the physical-right slider selects the application name (text) size. This is one custom control owned entirely by this specification; it is not the platform-standard slider.
- Each slider draws one right-triangle track silhouette: a horizontal bottom edge, a tall vertical left edge, and a top edge sloping linearly down to the right end, so the height at every position decreases from left to right. The three snapping stops sit at the left end, the horizontal midpoint, and the right end, and the silhouette height at each stop decreases from Large through Medium to Small. The track portion left of the thumb and the thumb use shared `primaryTextColor`; the track portion right of the thumb uses the shared `secondaryTextColor` treatment. No additional color token is introduced.
- One vertical bar-shaped thumb sits on the track at the selected stop, and its position alone expresses the current tier: the control displays no current-tier text and no other indicator. The author accepted the calibrated values on 2026-09-21: the left and right track heights are `20dp` and `8dp`; the thumb is `40dp` high, `4dp` wide, and has `2dp` corners; the track stays `6dp` clear on each side of the thumb.
- Each slider exposes its localized label — application size for the physical-left slider and text size for the physical-right slider — the current tier name, and the standard localized range actions, each moving one tier; a slider that its host behavior disables reports unavailable and does not change the tier. Interaction semantics — previewing, committing, haptics, and conditional enablement — belong to each host's behavior specification.
- The background block combines one percentage readout and one platform-standard continuous progress slider on its `48dp` content line, using the shared `12dp` start and end content insets. The readout sits at the physical left inside one fixed-width reservation sized to fit the complete widest value `100%`, so the slider geometry remains constant across all values; its text is center-aligned within the reservation. A `16dp` gap separates the readout from the slider. The slider fills the remaining line width with an interaction target spanning the full line height and exposes the continuous `0`–`100` percentage range without tick marks.
- The readout displays the current integer percentage through one localized format string, updates live during a drag, and is read-only: it is not an interaction target and exposes no separate focus target. Its text uses normal-weight shared `secondaryTextFontSize` with its line height in `primaryTextColor`.
- The slider's active track and thumb use shared `primaryTextColor` as their single accent color; the inactive track uses the shared `secondaryTextColor` treatment. No additional color token is introduced; accessibility announces the current percentage value.
- Enabled, selected, disabled, focus, Ripple, text, and icon treatment follows [Design foundations](../design-foundations.md). Temporary operation locks, including saving and selection animations, preserve control colors and opacity while rejecting activation and exposing disabled semantics; they do not grey out selectors, values, or otherwise available stepper actions. Stepper actions at a count boundary retain the shared disabled opacity. A host may omit an inapplicable setting block but may not restyle a shared line or render a disabled placeholder unless its behavior contract requires one.
